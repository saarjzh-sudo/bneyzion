- **commit `9fe5c718`** (self-heal ל-chunk-cache) — **שבר את NetSpark** ("supabaseUrl is required"). לא לקדם אותו כמו שהוא.

### שתי מלכודות הדיפלוי (חובה לפתור לפני קידום)
1. **NetSpark:** `client.ts` מקודד URL+key ב-base64 כי NetSpark מסיר אזור ~10KB מה-bundle. **שביר-לפי-layout** — שינוי קוד מזיז את המחרוזת, ואם נופלת באזור הנמחק → URL ריק → קריסה. **בדיקה:** `curl "https://bneyzion.vercel.app/assets/main-<hash>.js"` **בלי `--noproxy`** → `grep -c "aHR0cHM6Ly9wenZtd2ZleGVpcnVlbHdpdWp4bi5zdXBhYmFzZS5jbw"` → 1=בטוח, 0=ישבור.
2. **Chunk-cache:** דחיפה משנה hashים; טאב ישן-פתוח מבקש chunk שלא קיים → 404 → דף נשבר (זו הייתה תקלת הסליקה הראשונה). צריך self-heal + לומר לסער+יואב לרענן אחרי דחיפה.

### תוכנית הדחיפה הבטוחה (שלב 1)
א. **לעשות את ה-config חסין-NetSpark:** להזריק את ה-base64 של URL+key ל-`index.html` (`<script>window.__SB={u:'...',k:'...'}</script>`), ו-`client.ts` יקרא מ-`window.__SB` עם fallback לקבועים. כך ה-config יוצא מה-bundle המתחלף ל-HTML היציב (`max-age=0`). **לבדוק דרך NetSpark שה-base64 שורד ב-index.html.**
ב. להחזיר את ה-self-heal (main.tsx) — אחרי שה-config כבר לא ב-bundle, layout-shift לא ישבור את ה-URL.
ג. build → לקדם דיפלוי → **מיד `curl` דרך NetSpark לוודא base64=1** → אם 0, לגלגל אחורה מיד.
ד. לעשות זאת כשסער זמין לעקוב + לומר לו+ליואב לרענן (Ctrl+Shift+R).
