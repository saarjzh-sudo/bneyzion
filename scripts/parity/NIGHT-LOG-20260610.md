# Night session — bneyzion migration deep-fix (10.6.2026, overnight, full authorization)

Saar found that the prior "100% migration" report was **false** (depth audit compared title-existence,
not lesson-count-per-series). He listed 6 broken fronts and authorized a full autonomous fix + deploy.

## Root cause (one sentence)
The Umbraco→Supabase migration **inverted the schema**: the old site organizes each book as
*event-series* (e.g. "מרד אבשלום | פרקים טו-יח" = 18 lessons together); the migration created
*rabbi/project series* (מוקלט, ושננתם, לב אהרון…), scattered each event's lessons across them with
massive duplication, and left the canonical event-series as empty `draft/category` placeholders
(hidden from the sidebar). Plus the public sidebar never filtered `audience_tags` → teacher
worksheets leaked into the public tree.

### B. Data fix — consolidation (already LIVE via Supabase)
Tooling: `scripts/parity/consolidate.py` (+ `sbq.py` SQL helper, `audit_series_depth.py` audit).
For each נביאים book: scraped the old-site event pages (authoritative lesson list, title+rabbi),
matched lessons in the DB, **populated the empty event placeholders**, promoted them `draft/category → active`.
- **Non-destructive + reversible.** Full backups: `lessons_bak_20260610_night`, `series_bak_…`, `topics_bak_…`, `series_links_bak_…`.
- **MOVE** only loose copies (orphan / draft / synthetic chapter-layer b2020001-*/b2020002-*).
- **COPY** (clone row) when the source is a real project/rabbi series → that series keeps its lesson.
  Tradeoff: adds ~3-4k duplicate rows (consistent with the existing 50%-dup model); neutralized by the
  display-dedup added to rabbi/series pages. A future physical-dedup pass can remove them (with FK care).
