## B. 28 NO_H1 — Timing Artifact (Not a Bug)

### Root Cause
The Playwright scanner used `wait_for_selector("h1", timeout=8000)` — 8 second timeout. All 28 "failing" lessons had `render_ms ~8200ms`, meaning they timed out at exactly the 8 second mark before the React component rendered the `<h1>`.

### Proof
- Screenshot of lesson `0034acdf` (ישעיהו פרק מ) clearly shows full page with h1, rabbi, series, audio player — all correct
- `curl` response: HTTP 200, ~250ms (same as passing lessons)
- DB data: all 28 lessons have valid `rabbi_id`, `series_id`, `status=published`
- The 28 "failing" lessons are identical in structure to the 12,615 passing ones

### Why Do These 28 Load Slower?
Likely a combination of:
- Supabase query cache miss on cold start (first request for that lesson in session)
- Audio player pre-load adds ~500ms
- Playwright running 8 parallel workers — some workers are slower due to CPU contention
- No structural difference in the DB data

### Fix Applied
None needed to production. Scanner script should be updated with `timeout=15000` for `wait_for_selector` (currently 8000) to avoid false positives in future runs.

### Scanner Improvement (for next run)
In `scripts/playwright-lessons-scan.py`, change line:
```python
await page.wait_for_selector("h1, [data-error], .error-boundary", timeout=8000)
```
to:
```python
await page.wait_for_selector("h1, [data-error], .error-boundary", timeout=15000)
```
